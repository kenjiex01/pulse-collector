## 16:20 — Fix Collect now Server Error on Windows desktops

**Why:** San Mateo Windows v0.1.5 showed a generic Server Error after ~50s on first Collect now (device online, no prior collect). NativePHP PHP is single-threaded and 512MB; a full K30 pull + insert + one giant S3 JSON was OOMing/blocking the UI.

**Files:**
- `app/Providers/NativeAppServiceProvider.php`
- `app/Support/CollectRunTracker.php`
- `app/Support/ManualCollectWorker.php`
- `app/Support/BiometricAutoCollectWorker.php`
- `app/Services/BiometricLogCollector.php`
- `app/Services/BiometricLogJsonExporter.php`
- `app/Http/Controllers/CollectorDashboardController.php`
- `app/Http/Controllers/DeviceStatusController.php`
- `app/Console/Commands/CollectBiometricLogsCommand.php`
- `resources/views/collector/dashboard.blade.php`
- `routes/web.php`
- `bootstrap/app.php`
- `config/biometric.php`
- `.env.example`

**Summary:**
- Manual Collect now on the desktop app starts a background PHP worker instead of running inside the HTTP request (avoids 500 + frozen status polls)
- Chunked punch inserts (`INSERT OR IGNORE`) and chunked S3 gzip uploads so a first full-device pull does not load everything into one payload
- NativePHP `memory_limit=1024M`, `max_execution_time=0`
- Collect failures return JSON with a real message instead of Laravel’s generic Server Error dialog
- Status TCP checks pause while a collect is running so they do not steal the ZkTeco session
- Next installer version: **0.1.6**
